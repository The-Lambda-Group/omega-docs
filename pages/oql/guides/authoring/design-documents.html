What you build

A Design Document block keeps one database page of results current from another database page. You give it an Input Table (the database page it reads), an Output Page (the database page it writes), a Service Account (the account its methods run as) and a Map method, and optionally a Reduce method. Whenever a row of the Input Table changes, the engine runs the methods and keeps one Output Page row per key. This guide counts orders per group: the orders A1, A2 (group A) and B1 (group B) give the Output Page rows ["A"] = 2 and ["B"] = 1. Every command below is the qo CLI in your selected workspace, and every reference is a path, never an id. The same verbs are MCP tools named block_design_document_create, _status, _get, _update, _resume, _rebuild and _delete.

1. The Input Table

qo add-page "" "Orders" --database
qo page set-columns "Orders" '["Name","Group","Amount"]'
qo page set-primary-key "Orders" '["Name"]'
qo write "Orders" --data '{"header":["Name","Group","Amount"],"rows":[["A1","A","1"],["A2","A","2"],["B1","B","3"]]}'

2. The Output Page

You make the Output Page; the block never creates, owns or changes its columns. It must have exactly the text columns Key (the primary key) and Value.

qo add-page "" "Orders per group" --database
qo page set-columns "Orders per group" '["Key","Value"]'
qo page set-primary-key "Orders per group" '["Key"]'

3. The page that holds the block, and its Service Account

The Map and Reduce methods run as this account, never as you. To name an account in a Design Document you need read and write permission on it (its owner, or an Admin of the workspace).

qo add-page "" "Reports"
qo block service-account create "Reports" counter

4. The Map and Reduce methods

Methods are OQL clauses of a component. The Map method receives one row and binds Result to [Key Value]: here every order emits its group with the value 1 (several solutions would emit several rows). The Reduce method receives the values of one key and sums them; it must be associative and commutative (a sum, count, minimum or maximum), because the engine combines partial results in any order.

mkdir -p count-methods/Notes count-methods/protocols count-methods/implementations
cat > count-methods/.page.json <<'EOF'
{"name":"count-methods"}
EOF
cat > count-methods/component.json <<'EOF'
{"name":"Count Methods","type":"omega/query-omega/component/Component"}
EOF
cat > count-methods/Notes/.page.json <<'EOF'
{"name":"Notes"}
EOF
cat > count-methods/protocols/CountMethods.json <<'EOF'
{"functions":[{"name":"map-group","args":["self","row"]},{"name":"sum","args":["self","input"]}]}
EOF
cat > count-methods/implementations/CountMethods.json <<'EOF'
{"protocol":{"name":"CountMethods","external":false},"component":{"name":"Count Methods","external":false},"name":"CountMethods"}
EOF
cat > count-methods/implementations/CountMethods.oql <<'EOF'
(datastore Qo.Public.OqlApi.Impl "omega/query-omega/public/oql-api/implementation")

(:- (MapGroup Exec Result)
    (get Exec "args" Args)
    (get Args 0 Row)
    (get Row "values" Vs)
    (get Vs "Group" G)
    (= Result [G 1]))

(:- (Sum Exec Result)
    (get Exec "args" Args)
    (get Args 0 Input)
    (get Input "values" Vs)
    (get Vs I V)
    (with-unique-by [I] (fold 0 V + Result)))

(= Clauses {"map-group" {"2" MapGroup} "sum" {"2" Sum}})
(get $$ARG$$ "implementation-id" ImplId)
(Qo.Public.OqlApi.Impl/set-implementation-clauses ImplId Clauses _)
(return ["ok"])
EOF
qo add-page "" "Libraries"
qo add-page "Libraries" "count-methods"
qo push --source count-methods --library-page-path "Libraries/count-methods"

5. Create the Design Document

The block is named Reports@orders-per-group: the page that holds it, then its name.

qo block design-document create "Reports@orders-per-group" \
  --input "Orders" --output "Orders per group" --service-account "Reports@counter" \
  --map-page "Libraries/count-methods" --map-protocol CountMethods --map-method map-group \
  --reduce-page "Libraries/count-methods" --reduce-protocol CountMethods --reduce-method sum

6. Wait for it, then read the result

The status is running while the engine catches up, in sync when it is current, retrying, or failed with your method's error message. The Output Page rows are written a moment after the status turns in sync: if a row is missing, read again.

until qo block design-document status "Reports@orders-per-group" --json | grep -q '"in sync"'; do sleep 2; done
qo query "Orders per group" --limit 100

Expect two rows: Key ["A"] with Value 2, and Key ["B"] with Value 1. A Key is the JSON text of the key your Map emitted.

7. Change the input, watch the output follow

qo write "Orders" --data '{"header":["Name","Group","Amount"],"rows":[["B2","B","4"]]}'
qo query "Orders per group" --limit 100

Group B now has two orders, so Key ["B"] reads 2 once the engine has caught up.

8. Update merges

update changes only the fields you name and keeps the others. A method is named by all three of its flags. An update that names no field is refused. A Reduce cannot be removed by an update: delete the block and create it again without one.

qo block design-document update "Reports@orders-per-group" \
  --reduce-page "Libraries/count-methods" --reduce-protocol CountMethods --reduce-method sum
qo block design-document get "Reports@orders-per-group"

The document keeps its Input Table, Output Page, Service Account and Map method; the update replays it, so the Output Page stays current.

9. Resume, rebuild, delete

qo block design-document rebuild "Reports@orders-per-group"
qo block design-document delete "Reports@orders-per-group"

resume runs a failed document again after you fix its method; rebuild replays it from the start. delete stops the document and changes nothing else: the Output Page keeps its rows, and the Input Table, the Output Page and the Service Account stay. While a document refers to a page or an account, deleting that page or account, or changing the page's columns, is refused; delete the block first.
