HTTP Hooks

Visibility

Owner: omega | Workspace: OmegaAI | Visibility: Public

What are HTTP hooks?

OmegaDB can receive inbound HTTP requests and route them to OQL. Any connector can register an OQL functor as an HTTP handler. OmegaDB issues a stable URL (https://db.queryomega.com/hook/<uuid>) that external services can call. Use cases: OAuth callbacks, Stripe/LinkedIn/GitHub webhooks, and any external-triggered OQL execution.

Registering a hook

Use Qo.Public.Api.HttpEndpoint/register to register a functor as an HTTP handler. Pass the functor; the clause returns a map with the hook "id" and stable "url".

(datastore MyDs "my/component/handler")
(functor "my-handler" 2 MyDs HandlerFunc)
(datastore Ep "omega/query-omega/public/api/http-endpoint")
(Ep/register HandlerFunc Result)
(return [Result])

Result shape:

{"id"  "<uuid>"
 "url" "https://db.queryomega.com/hook/<uuid>"}

The call site uses register (no bang). The ! suffix appears only on the definition side of the deployed handler clause — it is not part of the call.

Writing a handler

The handler clause receives two arguments: Exec (the inbound request map) and Result (the output unification variable).

Exec map shape:

{"endpoint-id"   "<uuid>"
 "method"        "GET"
 "headers"       {"content-type" "application/json"}
 "query-params"  {"code" "abc123"}
 "form-params"   {}
 "body"          "raw string or nil"}

A form-urlencoded POST (Content-Type: application/x-www-form-urlencoded, the shape OAuth token endpoints use) arrives already parsed in "form-params", a map of field name to value, and "body" is nil. Any other body arrives as the raw string in "body", and "form-params" is {}.

The handler must unify Result with a response map containing "status" (integer), "headers" (map), and "body" (string).

Required response map shape:

{"status"  200
 "headers" {"Content-Type" "text/plain"}
 "body"    "ok"}

Minimal handler:

(:- (MyDs/my-handler! Exec Result)
    (= Result {"status" 200 "body" "ok" "headers" {}}))

Examples

OAuth callback (GET, reads query params)

(:- (MyDs/oauth-callback! Exec Result)
    (get Exec "query-params" Qp)
    (get Qp "code" Code)
    ;; exchange Code for tokens, store them
    (= Result {"status" 302
               "headers" {"Location" "https://app.queryomega.com/success"}
               "body" ""}))

Form POST (reads form-params)

(:- (MyDs/token-endpoint! Exec Result)
    (get Exec "form-params" Form)
    (get Form "grant_type" GrantType)
    ;; answer the form
    (= Result {"status" 200 "body" GrantType "headers" {"Content-Type" "text/plain"}}))

Webhook (POST, reads body)

(:- (MyDs/stripe-webhook! Exec Result)
    (get Exec "body" Body)
    (json-parse Body Event)
    ;; process Event
    (= Result {"status" 200 "body" "received" "headers" {}}))

Getting the URL

Use get-url to retrieve the hook URL by id:

(Ep/get-url Id Url)
(return [Url])

Returns "https://db.queryomega.com/hook/<uuid>".

Unregistering a hook

Use unregister with the id to remove a hook:

(= Id "<uuid>")
(Ep/unregister Id Result)
(return [Result])

Returns {"deleted" true}.

Security note

HTTP hooks have no authentication. The UUID provides security through obscurity — do not expose hook URLs in client-side code. Rate limiting and authentication are future work.

A handler runs with no caller credential: the request carries none, so terms that check the caller's permission on a page (for example Qo.Public.OqlApi.Page.Bl.PushCon/get-by-name) fail inside it. A component's handler reads its own page's settings with Qo.Page.PageProp/prop-data, and its push connectors with Qo.Page.Bl/page-block and Qo.PushCon/push-connector. Check everything the request claims (for an OAuth callback, a one-time state) before acting on it. Worked example: Public/OAuth.
