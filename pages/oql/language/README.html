OQL Language Reference

Core language constructs for writing OQL. These docs cover what the language provides and how it behaves — the authoritative reference for clause definition, control flow primitives, built-in terms, solution reducers, query execution strategies, and the hard rules that exist because every one of them has produced real data loss or silent wrong-answer bugs in production.

Visibility

Contents

  • Core Language Mechanics — Clause definition and capture semantics, control flow primitives (when/when-not/if/with-table-if), and the S-expression evaluation model. The foundational mechanics before writing any OQL clause.
  • Built-in Terms — The vocabulary of built-in term solvers: core primitives, arithmetic, map/array/string operations, HTTP, and the constraint that functor names must not shadow built-ins.
  • Query Execution — Solution reducers (fold, with-count, with-order-by, etc.) and index-selection strategies (defterm PK, write-index, Mango fallback). Required reading for any query that aggregates, sorts, or must avoid full-scan throws.
